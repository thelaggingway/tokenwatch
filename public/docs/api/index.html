Public JSON API

All endpoints accept GET requests and return JSON with permissive CORS headers. List endpoints paginate with limit and offset; the limit is clamped to 1–500 and defaults to 100. Malformed parameters return 400 with a stable code. Successful responses are compact JSON (add pretty=1 to indent), cacheable for five minutes, and carry an ETag, so a request with If-None-Match returns 304 when nothing changed. A machine-readable OpenAPI 3.1 description is also available.

Recommendation mixes are assumed workload defaults, not claims about your traffic. Model picks include best quality, best value, and the cheapest model above an absolute quality floor; explanations label benchmark coverage, provider ranking, missing signals, and confidence. Provider ranking requires confirmed capability and context metadata and keeps unverified options separate.

For chat-assistant and creative-writing, /api/v1/recommend also returns preference separately from model picks: the Arena favorite, board, rating, eligible providers, and source metadata with linked dataset, rating date, attribution, and CC BY 4.0 license. Creative writing is preference-led; chat picks remain capability-ranked. The source metadata lets API consumers display the required attribution alongside Arena ratings.

Recommendation responses default to compact candidate groups (up to 10 rows each, with total counts) and full explanations on the three model picks. Provider results keep full explanations on the top three. Add detail=full to expand explanations for returned rows, or set limit=1..100 to change each group cap. Recommendation JSON is compact (no indentation); add pretty=1 for indented output.

Recommendation parameters

The recommendation endpoints power the open model finder. Unknown values return HTTP 400 naming the rejected parameter; an unknown model returns 404.

  • use_case (required): agentic-coding, tool-agents, long-context-rag, structured-extraction, high-volume-cheap, chat-assistant, creative-writing, reasoning-math, frontend-ui.
  • model (required for /api/v1/recommend/providers): a canonical model ID from the catalog.
  • priority: balanced, cheapest, fastest, most-reliable (default balanced); re-weights provider ranking.
  • zdr=true: only providers marked zero data retention.
  • exclude_hq: comma-separated two-letter headquarters country codes to exclude; providers with unknown headquarters are not excluded.
  • include_proprietary=true: also consider models not confirmed open-weight.
  • detail: compact (default) or full; limit: rows per group, 1–100 (default 10); pretty=1: indented JSON.

Parameter reference

Every parameter below is documented with its type, default and the behaviour you should expect, including the cases where a value is accepted but has no effect. Prices in responses are USD per million tokens, and an unknown price or timestamp is null — never 0 and never "free". The same descriptions are published as JSON Schemas and parameter objects in the OpenAPI 3.1 document, including components.schemas for model rows, provider offerings, price history, recommendations and errors.

/api/v1/recommend

  • use_case (required) string — Workload preset id. See /api/v1/use-cases for each preset's assumed mix, weights, requirements and quality floor.
  • priority string, default balanced — Provider-ranking weights. balanced uses the use case defaults; the others re-weight price, time-to-first-token, throughput and uptime.
  • zdr boolean — When true, only providers marked zero data retention are eligible.
  • exclude_hq string — Comma-separated ISO 3166-1 alpha-2 headquarters country codes to exclude. Providers with unknown headquarters are kept, not excluded. A code that is not a real country code is a 400.
  • include_proprietary boolean, default false — When true, also consider models not confirmed open-weight. Defaults to open-weight models only.
  • detail string, default compact (compact, full) — compact returns summary rows with total counts; full adds explanations and per-provider detail to every returned row, which enlarges the payload by orders of magnitude.
  • limit integer, default 10 — Maximum rows per recommendation group (1–100), or at most 25 with detail=full. An out-of-range value is a 400 rather than a clamp.
  • pretty string, default 0 (1, 0, true, false) — When 1 or true, indent the JSON. Every data route returns compact JSON by default and honours this flag.

/api/v1/recommend/providers

  • use_case (required) string — Workload preset id. See /api/v1/use-cases for each preset's assumed mix, weights, requirements and quality floor.
  • model (required) string — Canonical model id from the catalog. Org prefixes, case and version suffixes are normalized, so openai/gpt-5 and gpt-5 resolve alike. An unknown id returns 404.
  • priority string, default balanced — Provider-ranking weights. balanced uses the use case defaults; the others re-weight price, time-to-first-token, throughput and uptime.
  • zdr boolean — When true, only providers marked zero data retention are eligible.
  • exclude_hq string — Comma-separated ISO 3166-1 alpha-2 headquarters country codes to exclude. Providers with unknown headquarters are kept, not excluded. A code that is not a real country code is a 400.
  • include_proprietary boolean, default false — When true, also rank providers of models not confirmed open-weight. Without it a closed model ranks no providers and returns an explanatory message.
  • detail string, default compact (compact, full) — compact returns summary rows with total counts; full adds explanations and per-provider detail to every returned row, which enlarges the payload by orders of magnitude.
  • limit integer, default 10 — Maximum rows per recommendation group (1–100), or at most 25 with detail=full. An out-of-range value is a 400 rather than a clamp.
  • pretty string, default 0 (1, 0, true, false) — When 1 or true, indent the JSON. Every data route returns compact JSON by default and honours this flag.

/api/v1/models

  • org string — Exact organization slug, matched case-insensitively against model.org.
  • provider string — Exact provider slug, matched case-insensitively against model.provider.
  • min_context integer — Keep offerings whose context window is at least this many tokens. Offerings with an unknown context window are excluded.
  • min_output integer — Keep offerings whose maximum completion tokens are at least this value. Unknown maximums are excluded.
  • min_intelligence number — Keep offerings whose benchmark intelligence_index is at least this value (decimals allowed, e.g. 45.5). Unbenchmarked offerings are excluded; 0 disables the filter. Negative or non-numeric values are a 400.
  • quantization string — Exact quantization label such as fp8, fp4, nvfp4, bf16 or unknown, matched case-insensitively.
  • open_weights boolean — Keep offerings with a resolved open-weight status of true or false. Unknown statuses are excluded from both, and null matches neither.
  • cache_read boolean — When true, keep only offerings that publish a cache-read tariff.
  • cache_write boolean — When true, keep only offerings that publish a cache-write tariff.
  • promo boolean — When true, keep only promotional offerings (discount > 0). A structural price has discount: 0.
  • zdr boolean — When true, keep only offerings from a provider marked zero data retention.
  • sub boolean — When true, keep only offerings available through a subscription plan.
  • benchmarked boolean — When true, keep only offerings carrying a benchmark sidecar.
  • search string — Case-insensitive substring match across model id, display name, org and provider.
  • sort string, default id (id, input, output, cache_read, cache_write, context, max_output, uptime, discount, intelligence, coding, agentic) — Sort key. Prices are USD per million tokens; context, max_output and uptime are offering metrics; intelligence, coding and agentic are benchmark indices. Null values sort last in both directions. An unknown key is a 400 listing the valid keys.
  • order string, default asc (asc, desc) — Sort direction, case-insensitive (DESC works). Any other value is a 400.
  • limit integer, default 100 — Page size, a positive integer. Values above 500 are clamped to 500 and the response limit reports the applied value; 0, negative, fractional or non-numeric values are a 400.
  • offset integer, default 0 — Zero-based index of the first row, a non-negative integer; anything else is a 400. An offset past the end returns an empty page with an honest total.

/api/v1/models/:canonicalId/providers

  • tokens number — Positive token count. It scales the cost figure only and never changes the order; zero, negative or non-numeric values are a 400.
  • mix string — Comma-separated input, cached-input, output percentages used to blend each offering's rates. Must sum to 100, validated like /history. When present, offerings sort by the blended rate at this mix with unpriceable offerings last; tokens is not required. Without it, offerings sort by input + output, unpriced offerings last.

/api/v1/models/:canonicalId/history

  • days integer, default 90 — Window length in days, today inclusive. Values outside 1-90 or non-numeric return 400.
  • mix string — Three percentages (fresh input, cached input, output) summing to 100 ±0.5, blended at read time against the stored raw tariffs. Malformed mixes return 400. Defaults to the agentic mix 2.5, 97, 0.5.

/api/v1/providers

  • zdr boolean — When true, keep only providers whose metadata says retains_prompts: false.

/api/v1/images

  • org string — Exact organization slug, matched case-insensitively.
  • provider string — Exact provider slug, matched case-insensitively.
  • search string — Case-insensitive substring match across id, name, org and provider.
  • sort string, default id (id, org, provider) — Sort key, compared case-insensitively. An unknown key is a 400 listing the valid keys.
  • order string, default asc (asc, desc) — Sort direction, case-insensitive (DESC works). Any other value is a 400.

Errors and freshness

Malformed model-ID encoding returns HTTP 400, unknown routes return 404, and unavailable catalog assets return 503. Every catalog response includes its source generation timestamp. Raw API and JSON files are marked noindex; this page is the crawlable reference.
