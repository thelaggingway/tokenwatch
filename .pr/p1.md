Part 1 of a 4-PR stack hardening `/api/v1`. **No response shape changes** in this PR; it only corrects values and ordering.

## What changed

**1. `blendedRate` no longer turns "no price" into $0** — `shared/cost.mjs`, mirrored in `public/app.js`

The cache leg was `crPrice != null ? … : null` then folded in with `(crRate || 0)`, so an offering with no `input`, `output`, or `cache_read` priced as **$0** and could win a cheapest-provider comparison. Now:

- a leg with a nonzero share and no price → `null` (including the cache-read leg when both `cache_read` and `input` are null),
- an all-zero mix → `null` (nothing is priced, so there is no rate),
- a genuinely published `$0` rate → still `0`.

Per repo convention `public/shared/cost.mjs` is regenerated by `generate-seo.mjs` and must stay byte-identical; `test/browser-shared-parity.test.mjs` guards it and passes.

**2. `/models/:id/providers` default ordering** — an unpriced offering used `pricing.input || 0` and sorted as the cheapest. New `listCost()` returns `Infinity` when both input and output are missing, so unpriceable offerings rank after every priced one. `??` is used so a published `0` is preserved.

**3. `/models?sort=discount`** — `discount` was in `validSorts` but the comparator fell through to `pricing[sortKey]`, and `pricing.discount` exists on 0 of 1,828 catalog rows. Both sides compared `undefined`, so the comparator returned `1` unconditionally and `order=desc` was ignored. Now reads the top-level `discount`.

**4. Comparator antisymmetry** — a null/null pair returned `1` in both directions. Now returns `0`; nulls stay last in **both** directions.

**5. `/images/:id`, `/videos/:id`** — these used `.find(canonicalId(m.id) === target)`. `canonicalId` strips the org prefix and `-preview`, so collisions returned the wrong model: `GET /api/v1/images/google/gemini-3-pro-image` returned the `fal` `gemini-3-pro-image-preview` row at $0.15/image instead of Google's $120/M-token row. Now exact id first, canonical-id fallback second (the bare-canonical form still works).

## ScaleDown `output: 0` — investigated, left as-is

`scaledown/summarize` and `scaledown/extract` are not produced by a dedicated parser; they arrive through the OpenRouter endpoint path. The upstream source states $0 explicitly:

```
$ curl -s https://openrouter.ai/api/v1/models/scaledown/summarize/endpoints
ScaleDown  {"prompt":"0.00000004","completion":"0","discount":0.2}
```

`completion` is the string `"0"`, not absent. That is a published free-output tariff, so the parser correctly emits `0` rather than `null`. No change made.

## Behaviour changes to review

- A mix that requests cached tokens on an offering with **no** `cache_read` *and* no `input` price is now unpriceable (`null`) instead of $0. `test/price-history.test.mjs` had a test asserting the old $0 fallback; it now asserts the new contract. That is the one existing test I changed rather than added.
- `/models/:id/providers` ordering and `/models?sort=discount` ordering change for the affected rows.

## No preset moves

`test/fixtures/recommend-presets.json` is a golden capture of `shortlistModels` output (picks, quality ranking, Pareto frontier, and every group) for all nine use-case presets against the real committed `public/pricing.json`. `test/api-correctness.test.mjs` re-runs it and asserts identical picks and order. **All nine presets are unchanged**, so the cost-formula change is proven inert for recommendations. Capture script: `scripts/capture-recommend-presets.mjs`.
